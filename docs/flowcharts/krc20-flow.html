Architecture

The KRC-20 covenant uses Inter-Covenant Communication (ICC):

  1. DagLockKRC20 is deployed first → gets covenant ID D
  2. A KCC-20 branch is created with ownerIdentifier = D
  3. Settlement requires two UTXO inputs: the token branch + the DagLock fee gate
  4. KCC-20's checkSigs() verifies the DagLock covenant authorizes the transfer
  5. DagLockKRC20 does NOT track token balances — KCC-20 handles token conservation

Output Layout

  • output[0]: Token recipient (KCC-20 branch output)
  • output[1]: Treasury — receives inputValue of the DagLockKRC20 UTXO (exact fee)

The DagLockKRC20 UTXO's KAS value IS the fee. It's deployed with exactly the protocol fee amount.
